# Вариант alg | cisc | harv | hw | tick | binary | trap | mem | pstr | prob2 | superscalar



# Требования к архитектуре и реализации

## alg
- делаю маленький язык в стиле JS/Lua;
- есть переменные, арифметика, if, while, процедуры;
- есть строки;
- есть builtins для I/O;
- AST будет текстово печататься в тестах.

## cisc
- Инструкции переменной длины.
- Поддержка `register + memory` в одной инструкции.
- Наличие специальных регистров.
- Хотя бы одна инструкция с переменной арностью.

## harv
- Раздельные **IMEM** (память команд) и **DMEM** (память данных).
- Векторы прерываний и код — только в **IMEM**.
- Строки, переменные, стек и **MMIO** — только в **DMEM**.

## hw
- `Control Unit` реализован как логика состояний.
- Отсутствие микрокода.
- В коде это отдельный модуль или класс, а не интерпретатор микроопераций.

## tick
- Моделирование строго по тактам.
- Формирование лога на каждый такт.
- Возможность остановки на любом такте.

## binary
- Результат трансляции — файл `program.bin`.
- Наличие отладочного файла `program.dbg`:
  - адрес
  - hex
  - мнемоника

## trap
- Ввод данных через расписание `(tick, token)`.
- Обработчик прерывания пишется на целевом языке.
- При входе в `trap` сохраняются:
  - `EPC`
  - `CAUSE`

## mem
- Ввод-вывод организован через **MMIO**.
- `IN_*` и `OUT_*` представляют собой адреса в **DMEM**.

## pstr
- Формат строки в памяти:
  - сначала длина (`len`)
  - затем символы
- Статические строки размещаются в `data section`.
- Операции над строками реализуются через runtime-процедуры.

## superscalar
- Первая реализация: `2-way in-order`.
- Параллельный выпуск (`issue`) только для независимых инструкций.
- Обязательное наличие `hazard detection`.
